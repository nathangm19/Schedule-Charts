SNT WWP Builder — User Guide

One Copilot agent turns the current Interiors Planner takt schedule into the week's extract, a draft Weekly Work Plan tab, and two interactive crew-loading dashboards — in a single run, in about two minutes.

What it produces

DeliverableWhat it is
Planner_Extract.xlsx / .csv Every activity decoded from the takt schedule's colored bars — trade, level, zone, start/finish dates — plus the workday calendar and the trade legend.
Planner_Extract_Week.xlsx / .csv Just the activities touching the target week.
SNT WWP Shared - WWP.xlsx Your WWP workbook with a new tab, WWP MM.DD.YY - DRAFT, built in the house format: sections by floor/area, S X C day codes, org column, foremen pre-filled from prior weeks.
SNT-Crew-Loading.html Crews-per-day histogram, stacked by trade, filterable.
SNT-Gantt.html Waterfall Gantt by level and zone — trade filters, activity search, next-6-weeks spotlight, draggable day cursor with floating histogram.

Before you start — the one rule that matters

Upload the workbooks from your Downloads folder, not the OneDrive picker. When you attach a file by browsing OneDrive/SharePoint, Copilot passes a cloud reference that the pipeline cannot open. Download fresh copies of both workbooks to your computer first, then attach with Upload from this device. This is the single most common reason a run fails.

Running the pipeline — step by step

1

Download the two live workbooks

From the project's SharePoint, download the current versions of:

  • Interiors Planner (the takt schedule — the "Lookahead" tab)
  • SNT WWP Shared (the weekly work plan workbook)

Save both to your Downloads folder. Filenames don't have to be exact — the pipeline identifies each workbook by its contents, not its name.

2

Open the agent

In Copilot (M365), open Agents → SNT WWP Builder. If you don't see it, ask the owner to share the agent link with you.

3

Attach both workbooks

Click + in the message box → Upload from this device → select both files from Downloads. (Drag-and-drop from the Downloads folder also works.)

4

Ask for the run

For the upcoming week, just say:

Run the pipeline

For a specific week, name the Monday:

Run the pipeline for 2026-08-31
5

Check the first line of the report

The report always opens with the week it actually built:

TARGET WEEK: 2026-08-31 (user-specified)

If that date isn't the week you asked for, tell the agent:

Re-run with this exact command: python snt_pipeline.py 2026-08-31
6

Download the deliverables

The agent ends with download links for all seven files. Save them to the week's Runs folder (e.g. Runs\2026-08-31\) so each week's outputs stay together.

After the run — the human part

The new WWP tab is a DRAFT of the takt work only. Before the plan is real, the team still:
  • adds punch items (from the Daero Zero Punch export),
  • adds commissioning / testing activities,
  • adds Saturday work, comments, and constraints,
  • confirms foremen (pre-filled from prior weeks — verify them),
  • removes any work the team renegotiates in the weekly meeting.

UNRESOLVED rows

The report may list a handful of rows under "UNRESOLVED rows requiring human assignment" — bar colors that aren't in the Planner's trade legend. Those activities are still in the extract; they just need a person to say which trade owns them. Fix the legend in the Interiors Planner (or assign them by hand in the WWP tab) and they resolve themselves on the next run.

Weekly rhythm

  1. Thursday/Friday: download fresh copies of both workbooks, run the agent for the coming Monday.
  2. Friday planning: team reviews the DRAFT tab — adds punch, commissioning, Saturday work; confirms foremen; trims renegotiated work.
  3. Monday–Friday: track daily with the day codes; the dashboards are self-contained HTML — post them anywhere, no install needed.

If something goes wrong

SymptomFix
"Nothing to run: attach this week's Interiors Planner…" The attachments arrived as cloud references. Re-attach with Upload from this device from your Downloads folder.
Report shows the wrong week Tell the agent: Re-run with this exact command: python snt_pipeline.py YYYY-MM-DD (the Monday you want).
"DUPLICATE knowledge copies of …" The agent's knowledge files have extra copies. Ask the agent owner to open Agent Builder and delete the extras so exactly one of each file remains.
"MISSING from knowledge: …" A knowledge file was removed. The agent owner re-adds it from the SNT-Lookahead-WWP-Dashboard package.
A stage fails with a Python error The agent stops and shows the full error — nothing after the failed stage is built. Send the error text to the agent owner; don't ask the agent to patch the scripts (it's instructed to refuse, so every run stays reproducible).

Ground rules the agent follows

  • It runs the packaged scripts verbatim — it never rewrites them, so two people running the same files get the same answer.
  • It reads Excel only through the scripts, never by "previewing" the file itself.
  • It stops on the first error instead of improvising around it.
  • Every output states its basis; the WWP tab is always labeled DRAFT.
